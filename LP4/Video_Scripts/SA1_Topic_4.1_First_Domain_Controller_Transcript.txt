Welcome to Topic 4.1, Your First Domain Controller. This is where the pod stops being a group of separate servers and becomes a domain. You will learn what Active Directory Domain Services is, with its key words: domain, tree, forest and domain controller. You will meet the global catalog, the FSMO roles and sites. You will see why Active Directory depends on DNS, choose functional levels, promote DC01 with the wizard and with PowerShell, and prove the new domain works.

Active Directory Domain Services, or AD DS, is a Windows Server role. It keeps one central list of users, computers and groups. That list is a directory: a database of objects you can search. Each object, like the user Ann Lee or the computer SRV01, has attributes such as a name. The schema is the rulebook for which objects may exist. A domain controller runs AD DS, holds a copy of the directory and signs people in. For Server+, directory services is one more server role.

A domain is a group of objects that share one directory database and one set of policies. It has a DNS-style name, like sa1.lab. A child domain's name ends with its parent's name, like branch.sa1.lab. Domains in one continuous namespace form a tree. One or more trees form a forest. The forest is the outer security boundary, with one schema. Global catalog servers hold a partial copy of every object. The first domain you create is the forest root. Our pod: one forest, one tree, one domain.

A global catalog is a domain controller that also keeps a searchable summary of every object in the forest. The first DC is always one. Five special jobs are done by just one DC each, so changes never clash. These are the FSMO roles. Schema master and domain naming master are forest-wide. RID master, PDC emulator and infrastructure master exist once per domain. Sites map Active Directory to your physical network. A new forest has one site. In our pod, DC01 holds everything.

How does a computer find a domain controller? It asks DNS. It looks up an SRV record named underscore ldap, underscore tcp, dc, underscore msdcs, sa1.lab. The answer says: DC01.sa1.lab, port 389. Then an A record gives the address, 192.168.50.10. No DNS, no domain. When you promote DC01, the wizard creates two zones, sa1.lab and underscore msdcs.sa1.lab. Unlike the file-backed zone from Learning Plan 3, these are Active Directory-integrated. They live in the directory, replicate with it, and allow secure dynamic updates.

A functional level decides which Active Directory features a domain or forest can use, and so the oldest Windows Server version allowed as a domain controller. On Windows Server 2025, a new forest must be at the 2016 level or higher. The Windows Server 2025 level means every DC must run Windows Server 2025, and it unlocks larger database pages. The default usually matches the version you run. In the lab you use Windows Server 2025 for both levels. You can raise a level later, but not simply undo it.

Step one is installing the role. In Server Manager, choose Manage, Add Roles and Features. On Server Roles, select Active Directory Domain Services, then select Add Features so the tools come along. Click through and install. Here is the catch: the role alone does not make DC01 a domain controller. Server Manager shows a flag: configuration required. The link Promote this server to a domain controller opens the next wizard. In PowerShell, Install-WindowsFeature AD-Domain-Services with dash IncludeManagementTools does the same install.

The Active Directory Domain Services Configuration Wizard starts with Deployment Configuration. You get three choices: add a domain controller to an existing domain, add a new domain to an existing forest, or add a new forest. DC01 is the very first domain controller, so choose Add a new forest. Then type the root domain name, sa1.lab. Use two or more labels. A single-label name like sa1 causes problems later. At work, use a subdomain of a name your organization owns.

On Domain Controller Options, choose Windows Server 2025 for both functional levels. Keep Domain Name System server selected, so DC01 hosts the zones. Global Catalog is selected and greyed out, because the first DC must be a global catalog. Read only domain controller is greyed out too: an RODC needs a writable DC to copy from. You build one in Lab 4.4. Last, type the DSRM password. Directory Services Restore Mode starts DC01 with AD DS offline, for repairs. In the pod, use the password shown in NetLab.

Next come three quick pages. DNS Options shows a yellow message: a delegation for this DNS server cannot be created. That is expected. A delegation lives in the parent zone, and nobody runs a parent zone for dot lab. Leave Create DNS delegation cleared. Additional Options shows the NetBIOS domain name. Wait for SA1 to appear. That short name is what you type in SA1 backslash Administrator. Paths shows where the database, logs and SYSVOL go. Keep all the defaults.

Review Options lists every choice: a new forest, sa1.lab, NetBIOS SA1, Windows Server 2025 levels, global catalog and DNS. View script shows the same choices as a PowerShell command. Then the Prerequisites Check runs. You will see yellow warnings about an old cryptography setting and the DNS delegation. Yellow is fine here; a red error would stop you. When all prerequisite checks pass, select Install. When it is done, DC01 restarts by itself. The first start takes a few minutes.

Here is the PowerShell way. After installing the role, run Install-ADDSForest with dash DomainName sa1.lab, dash DomainNetbiosName SA1, dash InstallDns, and dash ForestMode and dash DomainMode set to Win2025, as in the wizard. The cmdlet asks twice for the safe mode administrator password, which is the DSRM password, and hides it. Never put that password in a script file. After the restart, sign in as SA1 backslash Administrator. The password is the same, because on the first DC of a new forest the local Administrator becomes the domain Administrator. A domain controller has no local user accounts. Run whoami to confirm. Then look at ipconfig slash all. The DNS server list now starts with the loopback addresses, colon colon one and 127.0.0.1. DC01 asks itself, because it hosts the zones. And the Tools menu now lists the Active Directory consoles.

Now prove it worked. Get-ADDomain, piped to Format-List, shows DNSRoot sa1.lab and NetBIOSName SA1, the names you typed. DistinguishedName is DC equals sa1, DC equals lab, the way the directory writes the domain name. DomainMode shows the Windows Server 2025 level. The three domain-wide FSMO roles all point at DC01.sa1.lab. Get-ADForest shows the two forest-wide roles, schema master and domain naming master, also on DC01. GlobalCatalogs lists DC01, and Sites shows the single default site. One server holds every role.

Next, DNS. Open DNS Manager on DC01. Under Forward Lookup Zones you see underscore msdcs.sa1.lab and sa1.lab. Inside sa1.lab, the underscore tcp folder holds SRV records for LDAP and Kerberos. Now test the lookup clients use: nslookup dash type equals SRV, then the long underscore ldap name. The answer is DC01.sa1.lab on port 389, plus its address. Last, run dcdiag slash q. Quiet mode prints only errors, so no output is good news. After a restart, wait a few minutes.

Four mistakes to avoid. One: clearing the DNS server box on the first DC. Without DNS there are no SRV records, and nobody finds the domain. Two: a single-label domain name, or a public name you do not own. Use sa1.lab in the lab, and a subdomain of your own name at work. Three: pointing DC01's DNS client at SRV01 or a public server. A DC asks itself. Four: treating the DSRM password as a throwaway. It is your way into restore mode, so keep it safe.

Time to check yourself. DC01 is now the first and only domain controller of sa1.lab. First: which DNS record type tells SRV01 where the domain controller is, and what does it hold? Second: why was Read only domain controller greyed out on Domain Controller Options? Third: after the restart, which DNS server does DC01 use, and why? Fourth: which two FSMO roles are forest-wide, and which DC holds all five roles in the pod? Pause the video now and answer each one.

Here are the answers. One: an SRV record. The name underscore ldap, underscore tcp, dc, underscore msdcs, sa1.lab points to DC01.sa1.lab on port 389, and an A record then gives 192.168.50.10. Two: the first DC must be writable. An RODC copies from a writable DC, and none exists yet. Three: DC01 uses itself, through loopback, because it hosts the Active Directory-integrated zones. Four: schema master and domain naming master are forest-wide. The other three are per domain, and DC01 holds all five.

Let's do it on DC01. It is still in a workgroup, with the static address 192.168.50.10. In Server Manager I add the AD DS role with its tools, then use the flag to promote the server. I choose Add a new forest, sa1.lab, keep Windows Server 2025 and DNS, and type the DSRM password, which is the password shown in your NetLab pod. I accept the delegation warning, check SA1, keep the paths, and peek at View script. Install. After the restart I sign in as SA1 backslash Administrator and run each check.

To wrap up. AD DS is a directory of objects, held by domain controllers. Domains group objects, trees share a namespace, and the forest is the security boundary. Clients find domain controllers through SRV records in DNS, so the DNS server box matters. To promote the first DC, choose Add a new forest, Windows Server 2025 levels, DNS server, and a DSRM password. Then verify with Get-ADDomain, Get-ADForest, DNS Manager, nslookup and dcdiag. Lab 4.1 practices all of this in about fifty minutes.
