Welcome to Topic 2.1, Roles and Features. Your servers have names and addresses now, but they do not do any real work yet. To give a server a job, you add roles and features. In this video you will learn the difference between roles, role services and features. You will walk through the Add Roles and Features Wizard page by page, and see how to remove things again. Then you will do the same with PowerShell, install a feature whose files are missing, and work on Server Core.

Let's sort out three words. A role is a main job the server does for other computers. DNS Server and DHCP Server are roles. A role service is one part of a role that you can add on its own. For example, File and Storage Services is a role, and File Server is one of its role services. A feature is a tool that supports the server or a role, but it is not a job for others. Windows Server Backup, .NET Framework 3.5 and Telnet Client are features.

You have two tools for this. On a Desktop Experience server, Server Manager has the Add Roles and Features Wizard. It shows every role and feature as a check box, adds management tools by default, and asks about anything your choice depends on. PowerShell does the same with three cmdlets: Get-WindowsFeature, Install-WindowsFeature and Uninstall-WindowsFeature. PowerShell works on Server Core and in scripts. One detail: the wizard shows display names, like Windows Server Backup, while PowerShell uses short names, like Windows-Server-Backup.

To start the wizard, open Server Manager, select Manage, then Add Roles and Features. The first page, Before You Begin, is a reminder. Check that the Administrator password is strong, the address is static, and updates are current. You can tick Skip this page by default. Next comes Installation Type. Choose Role-based or feature-based installation. That is the right choice for everything in this course. The other option, Remote Desktop Services installation, is only for building a Remote Desktop deployment.

On Server Selection you choose where to install. Keep Select a server from the server pool. The server pool lists the servers that this Server Manager manages. Right now that is only SRV01, with 192.168.50.20. Select it, and the wizard installs there. The other option, Select a virtual hard disk, adds roles to an offline VHD file, which is handy when you prepare virtual machines. In Topic 2.3 you will add SRV-CORE to the pool, so you can target it from here too.

The Server Roles page lists the roles with check boxes. Notice File and Storage Services is already partly installed. Every server has it. When you select a role, like DNS Server, a pop-up appears. It asks: Add features that are required for DNS Server? It lists the management tools, such as DNS Server Tools. Keep Include management tools checked and select Add Features. If you select Cancel instead, the role check box clears again. The tools do not have to be on the same server as the role.

Next is the Features page. The list is long and it scrolls, so the slide shows a short version. Two features matter today. Windows Server Backup is the one you add in Lab Part 2. And .NET Framework 3.5 is special: its files are not on the server at all. You will see the fix in a moment. Also, some roles add their own pages after Features. DNS Server, for example, adds an information page. Read those pages, then select Next.

The Confirmation page lists what will be installed. There is a check box called Restart the destination server automatically if required. Leave it clear in the labs, so you decide when to restart. For .NET 3.5 you also get a yellow warning: Do you need to specify an alternate source path? Select the link Specify an alternate source path, and type D colon backslash sources backslash sxs. That folder is on the Windows Server ISO, which is attached as drive D in your pod. Then select Install.

The Results page shows a progress bar. When it finishes, it says Installation succeeded on SRV01, or it tells you that a restart is needed. Here is a nice detail: you can select Close at any time. The installation keeps running in the background. To check on it later, select the Notifications flag at the top of Server Manager. It shows the feature installation task, and Task Details opens the full progress again. So the wizard never forces you to wait.

Removing works the same way, in reverse. In Server Manager, select Manage, then Remove Roles and Features. The pages are almost the same, without Installation Type. On the Features page, clear the check box of the feature you want to remove. A cleared box means remove. If other roles or features depend on it, a pop-up asks whether to remove them too, so read that list carefully. Then on Confirmation, select Remove. The same restart check box is there, and the same Results page follows.

Now PowerShell. Get-WindowsFeature lists roles and features. Use dash Name with wildcards to filter, or pipe it to Where-Object Installed to see only what is installed. Read the brackets: an X means installed, and an indented line is a role service or subfeature. Then read Install State. Available means the files are on the server and ready. Removed means the files are not on the server, so you need a source. And InstallPending or UninstallPending means a restart is needed to finish.

Install-WindowsFeature installs by name. Add dash IncludeManagementTools, because PowerShell does not add the tools unless you ask. Try dash WhatIf first. It shows the plan and installs nothing, so Restart Needed says Maybe. Then run it for real. The result has four columns. Success True, Restart Needed No, Exit Code Success, and Feature Result lists what was installed. Run it again and you get NoChangeNeeded with empty braces. That is not an error. The feature was already there, so nothing changed.

Where does Windows find a feature's files? First in the local store, the WinSxS folder. Second in the path you give with dash Source, or the wizard's alternate path. Third in a repair source set by Group Policy. Last, Windows Update. Our pod has no internet, so step four fails. .NET 3.5 is in the Removed state on a standard install, so give it dash Source D colon backslash sources backslash sxs. Without it, an offline server fails with an error that the source files could not be found.

To remove a feature, use Uninstall-WindowsFeature with the same name you used to install it. You get the same result object, so read Restart Needed. Yes means you must restart to finish. Afterwards, Get-WindowsFeature shows Available again. The files stay on the server, so you can reinstall any time without a source. There is also a dash Remove parameter. It deletes the files from WinSxS too, and the state becomes Removed. It saves disk space, but we do not use it in this course.

Server Core has no Server Manager window, so there is no wizard at the console. Instead, at the SRV-CORE console, choose option fifteen in SConfig to open PowerShell. Then use the same cmdlets. Check with Get-WindowsFeature, install with Install-WindowsFeature, and read the result object exactly the same way. In Topic 2.3 you will also manage SRV-CORE from Server Manager on SRV01, so the wizard can target it remotely. And remember, features that need the desktop are not offered on Server Core.

Here are four common mistakes. One: installing .NET 3.5 with no source on an offline server. It fails, so give the D colon sources sxs path. Two: expecting PowerShell to add the management tools. It only does with dash IncludeManagementTools. Three: calling NoChangeNeeded an error. Success is still True, the feature was simply already installed. Four: ignoring Restart Needed Yes. The change is not finished until you restart, so plan the restart and then check the Install State again with Get-WindowsFeature.

Time to check yourself. Imagine a classmate is busy adding features in the pod. First, is Windows Server Backup a role, a role service or a feature, and why? Second, Get-WindowsFeature shows NET-Framework-Core as Removed. What does the install need? Third, Install-WindowsFeature returns True, No, NoChangeNeeded. What happened? And fourth, they installed DNS Server with PowerShell, but the DNS console is missing. What did they leave out? Pause the video now, think about your answers, maybe write them down, then continue.

Here are the answers. One: Windows Server Backup is a feature. It supports the server itself and is not a service that other computers use. Two: it needs a source, dash Source D colon backslash sources backslash sxs, because the files are not on the server and the pod has no internet. Three: it was already installed. Success is True, and nothing needed to change. Four: they left out dash IncludeManagementTools. The wizard adds the tools by default, but PowerShell does not.

I'm on SRV01. First, PowerShell. Get-WindowsFeature shows Windows Server Backup as Available and .NET 3.5 as Removed. Now Server Manager, Manage, Add Roles and Features. Role-based, SRV01, no roles. On Features I tick Windows Server Backup and .NET Framework 3.5. Here is the yellow warning on Confirmation. I select Specify an alternate source path, type D colon backslash sources backslash sxs, and select OK, then Install. I can close the wizard while it runs. The Notifications flag shows the task. Done. Back in PowerShell, both features now show Installed.

To wrap up: roles serve other computers, role services are parts of roles, and features support the server. The wizard goes through Installation Type, Server Selection, Server Roles, Features and Confirmation. In PowerShell, Get-WindowsFeature shows the state, Install-WindowsFeature adds, and Uninstall-WindowsFeature removes. Removed features need a source. In Lab 2.1 you explore SRV01, add features with the wizard and from the ISO, work on SRV-CORE with PowerShell, and remove features. About forty-five minutes, practice only. See you in the lab.
