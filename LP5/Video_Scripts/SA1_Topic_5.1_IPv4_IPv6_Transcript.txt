Welcome to Topic 5.1, IPv4 and IPv6 for Servers, the first topic of Learning Plan 5 on addressing. You have typed IP addresses since Lab 1.4; now you will understand them. You will review the four IPv4 settings every server needs and why servers are static. You will spot private ranges and the APIPA address that signals trouble. You will work out a subnet and split a network. Then you meet IPv6: how to read, shorten, classify, set and test it.

Every server needs four IPv4 settings. Here they are for SRV01. The IP address, 192.168.50.20, identifies it on the network. The subnet mask, 255.255.255.0, or slash 24, says which part of the address is the network and which part is the host. The default gateway is the router to other networks; our pod has no router, so it stays empty. And the DNS server, 192.168.50.10, which is DC01. SRV01 sends anything inside 192.168.50.0 directly. Anything else would go to the gateway.

Why are servers static? Because DNS records, firewall rules and clients point at them. If a server's address changed, all of that would break. Next, the private ranges from RFC 1918: 10 slash 8, 172.16 slash 12, and 192.168 slash 16. Anyone can use them inside an organization, and they are never routed on the internet. Finally, APIPA. When a computer set to automatic gets no answer from DHCP, it gives itself a 169.254 address. On a server, the static address is missing.

Let's refresh subnetting with our own pod network. Slash 24 means 24 ones in the mask, so the first three octets are the network and the last octet, 8 bits, is the host part. All host bits zero gives the network address, 192.168.50.0. All ones gives the broadcast, 192.168.50.255. Everything between, .1 to .254, is usable. That is 2 to the power 8, which is 256, minus 2, so 254 hosts. Our servers, CLIENT01 and the DHCP scope all fit.

A campus owns 10.50.0.0 slash 16 and wants four subnets, one per building. Four is 2 times 2, so borrow 2 host bits. The prefix grows from 16 to 18, and the mask becomes 255.255.192.0. The block size is 256 minus 192, which is 64, so subnets start at 0, 64, 128 and 192 in the third octet. Each has 14 host bits, so 16,382 hosts. Check: 10.50.130.7 sits between 128 and 191, so it is in 10.50.128.0 slash 18.

IPv6 addresses are 128 bits long, four times IPv4. They are eight groups of four hexadecimal digits, zero to nine and a to f, separated by colons. A subnet is almost always slash 64: the first 64 bits are the network prefix, and the last 64 bits are the interface ID, the host part. IPv4 has about 4.3 billion addresses, and the world ran out. IPv6 gives every single subnet 2 to the power 64 addresses. Our pod prefix is fd00:50:: slash 64.

There are two shortening rules. Rule one: drop the leading zeros in each group. 0050 becomes 50, and 0000 becomes a single 0. Zeros at the end stay, so fd00 stays fd00. Rule two: replace one run of all-zero groups with a double colon. Only once, or nobody could tell how many zeros each one hides. Our long SRV01 address becomes fd00:50::20. To expand, work backwards: fill each group to four digits, then add zero groups until there are eight.

You will meet five kinds of IPv6 address. Link-local starts with fe80. Windows makes one on every adapter; it works only on the local link. Unique local addresses, fc00 slash 7, with fd00 actually in use, are the private ones, like RFC 1918. Global unicast, 2000 slash 3, are public. The loopback is colon colon 1, like 127.0.0.1. And multicast starts with ff; IPv6 has no broadcast. The percent number after a link-local address is the zone ID, the adapter's interface index.

First, every host makes a link-local address, with no help. Then a router sends a Router Advertisement with the slash 64 prefix. The host adds its own interface ID. That is SLAAC, stateless address autoconfiguration, and no server is needed. It checks that nobody else uses the address, then starts using it. Flags in the advertisement can also send hosts to DHCPv6, either for the address itself or just for options like DNS. Our pod has no router, so you set static addresses.

Before you change anything, read what is there. ipconfig slash all on SRV01 shows DHCP Enabled: No, so IPv4 is static. Next comes a link-local IPv6 address starting with fe80. Windows made it, so yours is different, and you never write it down as a setting. Then the IPv4 address and mask you typed, an empty default gateway, and the DNS server 192.168.50.10, DC01. Every member of sa1.lab uses DC01 for DNS. Keep this output in mind: it is your baseline.

Here is the GUI way. Open ncpa.cpl, right-click Ethernet and choose Properties. Select Internet Protocol Version 6, TCP slash IPv6, and keep its box checked. Then select Properties. Choose Use the following IPv6 address. For DC01, type fd00:50::10. In Subnet prefix length, type 64. That is a number of bits, not a mask. Leave Default gateway empty, because the pod has no router, and leave the DNS boxes as they are. Then select OK, and Close the Ethernet Properties window.

Every GUI task has a PowerShell twin. On a new server, find the adapter name with Get-NetAdapter. Then New-NetIPAddress with the interface alias, the IP address and dash PrefixLength 24. Then check with ipconfig that DHCP Enabled shows No. With a router you would add dash DefaultGateway. Set-DnsClientServerAddress sets the DNS server list. Finally, Get-NetIPConfiguration is the PowerShell version of ipconfig. SRV01 already has these values from Lab 1.4 and Lab 4.3, so in the lab you only read them.

For IPv6 you use the very same cmdlet. New-NetIPAddress, interface Ethernet, IP address fd00:50::20, prefix length 64. Windows sees the colons and creates an IPv6 address. Then Get-NetIPAddress with dash AddressFamily IPv6 lists the IPv6 addresses. Your new one shows PrefixOrigin Manual, because you typed it. The link-local one shows WellKnown; it stays, and that is fine. The loopback colon colon 1 sits on its own pseudo-interface. Set-DnsClientServerAddress also accepts IPv6 DNS server addresses, if a network ever needs them.

Now test. One catch first. In Lab 1.4 you opened ping for IPv4 only. IPv6 ping uses ICMPv6, and it has its own firewall rule: File and Printer Sharing, Echo Request, ICMPv6-In. Enable it on each computer you want to ping. Then ping dash 6 forces IPv6. Ping DC01 at fd00:50::10 and you should get four replies. Test-Connection is the PowerShell ping; here it reaches CLIENT01. Test by address in this lab, and you will see why on the next slide.

When a name has both IPv4 and IPv6 addresses, Windows prefers IPv6 global addresses by default. A prefix policy table decides, and Get-NetPrefixPolicy shows it. A detail: that table ranks unique local addresses below IPv4, so in our pod names may still answer on IPv4. Now the important rule. Microsoft does not recommend disabling IPv6. Windows uses it internally, and on a domain controller LDAP over UDP 389 stops working. If IPv4 really must win, set DisabledComponents to hex 20 instead.

Four mistakes to avoid. One: typing a dotted mask or slash 24 for an IPv6 address. IPv6 uses a prefix length, normally 64. Two: using the double colon twice. Use it once, for the longest run of zero groups. Three: clearing the IPv6 check box to keep things simple. Keep IPv6 bound, and prefer IPv4 with hex 20 if needed. Four: ping dash 6 times out, so you retype the address. Check the firewall first, because the ICMPv6 rule is separate.

Time to check yourself. First, a file server shows 169.254.20.7. What does that tell you, and what is the fix? Second, how many hosts fit in 10.50.64.0 slash 18, and what is its broadcast address? Third, shorten fd00:0050 followed by five zero groups and 0020, and say what type of address it is. Fourth, a colleague wants to clear IPv6 on DC01 because we only use IPv4. What do you say? Pause the video, answer in your own words, then continue.

Here are the answers. One: that is APIPA. The adapter is on automatic and no DHCP server answered. Give the server its static address. Two: slash 18 leaves 14 host bits, so 16,382 hosts, and the broadcast is 10.50.127.255, just before the next subnet at 10.50.128.0. Three: fd00:50::20, a unique local address, because fd00 slash 8 is the ULA range in use. Four: keep IPv6 enabled. Microsoft does not recommend disabling it, and Active Directory on DC01 depends on it.

Let's do it in the pod. On SRV01, ipconfig slash all shows a static IPv4 address and a link-local IPv6 address that Windows made. On DC01, I open the TCP slash IPv6 properties, choose Use the following IPv6 address, type fd00:50::10 with prefix length 64, and select OK. On SRV01, New-NetIPAddress adds fd00:50::20, and Get-NetIPAddress shows it as Manual. With the ICMPv6 echo rule enabled and CLIENT01 addressed, ping dash 6 gets replies. Finally, Get-NetPrefixPolicy shows why we test by address.

To wrap up: a server needs an address, a prefix, a gateway if there is a router, and DNS, and it is static. Read 169.254 as a DHCP problem. A subnet has a network address, a host range and a broadcast, and you borrow bits to split it. IPv6 is 128 bits, slash 64, shortened with two rules. Keep it on.
