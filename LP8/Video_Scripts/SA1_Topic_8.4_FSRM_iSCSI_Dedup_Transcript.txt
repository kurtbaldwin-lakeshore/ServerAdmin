Welcome to Topic 8.4, the last topic about storage and file services. You will meet three tools that every file server administrator uses. First, File Server Resource Manager, or FSRM, which limits how much data users store and which kinds of files they may save. Second, iSCSI, which gives a server a disk over the network, from another Windows server or from a NAS appliance. Third, Data Deduplication, which stores repeated data only once. By the end you can set them up with the GUI and with PowerShell.

File Server Resource Manager is a role service of File and Storage Services. It answers two questions about a folder: how much may users store, and what may they store. Quota management limits space. File screening controls file types. Storage reports show you usage, large files, duplicates and screening attempts. Classification and file management tasks are concept only in this course. One limit to remember: FSRM works on NTFS volumes only, not ReFS. You install it with Install-WindowsFeature FS-Resource-Manager and open it from the Server Manager Tools menu.

A quota sets a space limit on a folder. A hard quota enforces it: once the folder is full, nobody can save more. A soft quota lets users go over and only sends notifications, so it is for monitoring. Notification thresholds fire at a percentage, for example a warning email at 85 percent. Quota templates save settings for reuse, like the built-in 100 MB Limit. An auto apply quota sits on a parent folder and gives every existing and new subfolder its own quota.

Here is the Create Quota dialog in the FSRM console. In Quota path, type the folder, C colon Shares Projects. Keep Create quota on path, so the quota covers this one folder. You can derive the settings from a template, or select Define custom quota properties and then Custom Properties. In the Quota Properties dialog, under Space Limit, type 100 and choose MB. Then select Hard quota, Do not allow users to exceed limit. Select OK and then Create. For one folder, skip saving the settings as a template.

This is the File Screen Properties dialog. Under Screening type, active screening blocks the files: the user gets Access denied. Passive screening lets the save happen and only notifies you. Under file groups, you pick what to block. A file group is a named list of patterns, and Audio and Video Files includes star dot mp3, star dot mp4, star dot wav and more. And if one subfolder needs audio files after all, a file screen exception allows that group again there.

The same work in PowerShell takes only a few lines. Install-WindowsFeature adds FSRM with its tools. New-FsrmQuota with dash Path and dash Size 100MB creates a hard quota, because you did not add dash SoftLimit. To use a template instead, add dash Template. New-FsrmFileScreen with dash IncludeGroup Audio and Video Files and the switch dash Active creates the active screen. Get-FsrmFileGroup shows the patterns in a group. Finally, Get-FsrmQuota shows the size in bytes, 104857600, and SoftLimit False, which tells you the quota is enforced.

Now to storage networking, a Server plus topic. A storage area network, or SAN, gives a server block storage. The server sees a raw disk and creates the file system itself. iSCSI sends disk commands over ordinary Ethernet, on TCP port 3260. The initiator is the client, here SRV01. The target is the storage server, here SRV-CORE, offering the target sa1-target. A LUN, a logical unit number, is one disk that a target offers. Compare that with a NAS, where you get a file share and the NAS owns the file system.

Every initiator and target has an iSCSI Qualified Name, or IQN. SRV01's IQN starts with iqn, then the year and month the naming authority owned its domain, then that domain reversed, com dot microsoft, and after the colon a unique name. A portal is the IP address and port where a target listens. A Windows target lists the allowed initiators. CHAP adds a shared secret, and mutual CHAP checks both sides; our lab uses none. In production, iSCSI runs on its own network or VLAN, and MPIO adds a second path.

SRV-CORE is Server Core, so you build the target in PowerShell. Install-WindowsFeature FS-iSCSITarget-Server adds the role service, with no restart. Create a folder, then New-IscsiVirtualDisk makes C colon iSCSI lun1 dot vhdx, 5 GB. Without dash UseFixed the file is dynamic and grows as data is written. New-IscsiServerTarget creates sa1-target, and dash InitiatorIds allows only SRV01's IQN. Add-IscsiVirtualDiskTargetMapping maps the disk to the target as LUN 0. Get-IscsiServerTarget then shows the target, its IQN and the status NotConnected, until SRV01 logs on.

On SRV01 you open the iSCSI Initiator, from Server Manager Tools or by running iscsicpl. The first time, Windows offers to start the Microsoft iSCSI service. Select Yes. On the Targets tab, Quick Connect finds the targets at an address and logs on. You can also add the portal on the Discovery tab, then select a target and Connect. The Connect To Target dialog can add the connection to Favorite Targets, so it returns after a restart. Connected means a new disk appears. The Configuration tab shows this server's initiator name, its IQN.

Here is the initiator side in PowerShell. The service is called MSiSCSI. Set it to start automatically and start it now. New-IscsiTargetPortal adds SRV-CORE's address as a portal, so discovery runs on TCP port 3260. Get-IscsiTarget lists what the portal offers, and you pick the target whose name contains sa1-target. Connect-IscsiTarget logs on, and dash IsPersistent true makes the connection come back after every restart. Get-IscsiSession confirms it: IsConnected and IsPersistent are both True. Forget IsPersistent and your disk disappears at the next reboot.

A NAS appliance like NAS01, running TrueNAS, can also be an iSCSI target. Same steps, other portal: 192.168.50.40. TrueNAS sets its own IQN prefix, so you match the target by its name, sa1-nas. On Windows Server, new disks on a shared bus often arrive offline, because of the SAN policy. Pick the right disk by its size, 10 GB here, never by its number alone. Bring it online, initialize it as GPT, create a partition N and format it NTFS with the label NAS.

Look at the three files. Each is cut into chunks, and many chunks are the same. The chunk store, in System Volume Information, keeps each unique chunk once, optionally compressed. Here twelve chunks of data need only five stored chunks. The files now hold reparse points that point to their chunks. It is post-processing: files are written normally, and a scheduled job optimizes them later. It works on data volumes, NTFS or ReFS, never on the system or boot volume. Server 2025 also has separate ReFS native dedup.

In Server Manager, go to File and Storage Services, Volumes. Right-click the data volume E colon and select Configure Data Deduplication. In the dialog, choose the usage type. General purpose file server is the usage type called Default in PowerShell. Virtual Desktop Infrastructure server is HyperV, and Virtualized Backup Server is Backup. Next, Deduplicate files older than, in days, defaults to 3. In the lab you set 0 so you can see results right away. You can exclude file types and folders, and the schedule button sets when jobs run.

In PowerShell, Install-WindowsFeature FS-Data-Deduplication adds the feature. Enable-DedupVolume with dash UsageType Default turns it on for E colon. Set-DedupVolume with dash MinimumFileAgeDays 0 is the lab shortcut. Then Start-DedupJob, type Optimization, with dash Wait, runs a job now and shows progress. Get-DedupStatus and Get-DedupVolume show saved space, optimized files and the usage type. Your numbers will differ from anyone else's. Normally you do not start jobs by hand: optimization runs about every hour, and garbage collection and scrubbing run weekly.

Four mistakes to avoid. One: choosing a soft quota or passive screening when you meant to block. Soft and passive only notify, so pick hard and active. Two: connecting two servers to the same LUN without a cluster. The file system gets corrupted. List only one server's IQN on the target. Three: connecting a target without making it persistent. After the next restart, the disk is gone. Four: expecting dedup to save space at once, or on C colon. It works on data volumes, after the minimum file age.

C colon Shares Projects has a 100 MB hard quota and an active Audio and Video Files screen. First, the folder holds 90 MB and a user saves a 20 MB file. What happens, and what would happen with a soft quota? Second, a user saves song dot mp3 there. What happens, and what would passive screening do? Third, in our iSCSI setup, which side is the initiator, and which port must reach SRV-CORE? Fourth, why can you not enable Data Deduplication on C colon? Pause and answer all four.

One: with the hard quota, the save fails, because 90 plus 20 is more than 100 MB. With a soft quota it would work, and you would only get notifications. Two: active screening refuses song dot mp3, and the user sees Access denied. Passive screening would save it and only notify. Three: SRV01 is the initiator and SRV-CORE is the target, so SRV01 must reach TCP port 3260 at 192.168.50.21. Four: C colon is the system and boot volume, and deduplication only runs on data volumes such as E colon.

Now the pod. On SRV01, I install FSRM and give the Projects folder a 100 MB hard quota and an active audio and video screen. Watch: the second 60 MB file fails with not enough space, and song dot mp3 gets Access denied. On SRV-CORE, I build sa1-target with a 5 GB virtual disk for SRV01 only. Back on SRV01, the iSCSI Initiator discovers the portal and connects as a favorite target, and the new disk becomes I colon. Last, I turn on deduplication for E colon and run an optimization job.

FSRM gives you quotas, file screens and storage reports on NTFS. Hard quotas block, soft quotas notify, and templates and auto apply quotas save work. Active file screens block file groups; passive screens only notify. iSCSI connects an initiator to a target and its LUNs, identified by IQNs, through a portal on TCP 3260. Make connections persistent, and expect new SAN disks to arrive offline. Deduplication works on data volumes with a chunk store and scheduled jobs. In Lab 8.4, about 90 minutes and practice only, you build all of this yourself.
