Welcome to Server Administration 1. This is Topic 1.1, called Server Hardware. Before you install Windows Server, it helps to know what it runs on. In this video you will look at how servers are built, how they are mounted in racks, how they get power and cooling, and how admins manage them from far away. You will also check what Windows Server 2025 needs from the hardware. It all applies to any brand of server you meet at work.

Here are the six things you will be able to do by the end. First, explain what makes a server different from a desktop PC. Second, read a rack diagram and count rack units. Third, name the main parts inside a server. Fourth, plan power and cooling, including a simple UPS estimate. Fifth, tell in-band from out-of-band management, and explain UEFI, Secure Boot and the TPM. And sixth, choose hardware for a workload and check the Windows Server 2025 minimums.

A server is not just a fast PC. A desktop runs during work hours for one person. A server runs all day, every day, for years, and many users depend on it. That changes the parts. Servers use ECC memory, which finds and fixes memory errors before they crash a service. They have spares built in: two power supplies, drives you can swap while the server runs, and RAID. And you can manage them remotely, even when Windows is down. Remember three words: reliability, redundancy and remote management.

Servers come in three main shapes, called form factors. A tower stands on the floor like a large PC. It suits a small office. A rack server bolts into a 19-inch rack on rails. Its height is measured in rack units, and many servers share one rack, its cables and its power. A blade is a thin server that slides into a chassis. The chassis shares power, cooling and network links with every blade, so blades are very dense. You find them at large sites.

Let's read a rack diagram. Each numbered space is one rack unit, or 1U, which is 1.75 inches high. You count from the bottom, so U1 is the lowest space. A 2U server takes two spaces, a 4U server takes four. Full-height racks are often 42U. Now count this rack with me: 1, plus 1, plus 2, plus 1, plus 4, plus 2 is 11U used. Only U10 is free, so a new 2U server will not fit anywhere in this rack.

A socket holds one CPU, and servers often have one or two sockets. Each CPU has several cores, and each core can usually run two threads at once. Multiply them: two sockets times eight cores times two threads gives 32 logical processors. Memory in a server is ECC, usually registered DIMMs of the current generation such as DDR5. Network adapters, or NICs, run at 1, 10 or 25 gigabit Ethernet. Teaming joins ports, so traffic keeps flowing if one cable or switch fails.

Drives connect through one of three interfaces. SATA is the low-cost choice for big drives, at up to 6 gigabits per second. SAS is the enterprise choice. It runs at 12 gigabits and has two ports, for a spare path to each drive. NVMe drives are solid-state and connect straight to PCI Express lanes, for the lowest delay. Hot-swap bays let you replace a drive while the server runs. A RAID controller joins drives so one failure loses no data. RAID levels come in Topic 8.1.

Each server has two hot-swappable power supplies, or PSUs, and either one can run the whole server. Follow the diagram: PSU 1 is fed by circuit A through UPS A and PDU A. PSU 2 uses the B path. If one circuit, UPS or PDU fails, the server keeps running. The UPS is a battery that takes over in a power cut. It gives you minutes, not hours. The PDU is the rack's power strip, and some PDUs can measure the load.

How big a UPS do you need? Follow four steps. One, add the watts of everything you plug in. Here that is 600 watts. Two, add 25 percent headroom, which gives 750 watts. Three, convert to VA by dividing by the power factor. This course uses 0.9, so you get about 834 VA. Four, pick a UPS where both ratings are higher, like 1000 VA and 900 watts. Why both? Watts are the real work, and many units have a lower watt rating than VA. Then check the runtime chart.

Servers breathe air from front to back. Fans pull cool air in at the front and push hot air out the back. In a server room, rows of racks face each other across a cold aisle, and stand back to back across a hot aisle. That way no server breathes another server's exhaust. Remember the blanking panels from the rack slide? Without them, hot air loops through the empty spaces back to the front, and the servers slowly heat up.

Windows has crashed and you are at home. You need out-of-band management. Most servers have a BMC, a baseboard management controller. It is a small computer with its own network port, on standby power. It works even when the server is off, as long as the power cord is in. Through it you can power the server on or off, see its screen, mount an ISO file as a virtual DVD. Vendors call it iDRAC, iLO or XClarity. The standards are IPMI and the newer Redfish.

Modern servers use UEFI, which replaced the legacy BIOS. UEFI boots from GPT disks, which can be larger than 2 terabytes, and supports Secure Boot. Secure Boot only runs boot loaders signed by a trusted key, which blocks boot-time malware. The TPM is a security chip that stores keys and records each step of startup. For Windows Server 2025, Microsoft lists UEFI with Secure Boot and a TPM as required only for certain features, such as BitLocker. If there is a hardware TPM, it must be version 2.0.

Here are the minimums from Microsoft Learn. The CPU must be a 1.4 gigahertz 64-bit processor with a few required features. Memory is 2 gigabytes for Server Core and 2 for Desktop Experience, with 4 recommended. Disk is 32 gigabytes, an absolute minimum. The network adapter must reach at least one gigabit per second. Two tips. A minimum is not a recommendation: size for your roles. And setup can fail in a VM with 1,024 megabytes, so give it 1,280 or more during setup.

Start with the workload, not the catalog. A small office file server can be a tower with one socket, moderate memory, and big drives in RAID. A virtualization host carries many virtual machines, so it gets two sockets, a lot of memory, fast SSDs, teamed 10 or 25 gigabit ports, and two power supplies on separate feeds. A branch domain controller is small, but nobody at the branch can fix it, so a UPS and a BMC matter most. Always ask: what happens if this server stops?

Windows can show you the hardware it sees. Run msinfo32 to open System Information, and stay on System Summary. Look for four rows. Processor shows the CPU name and how many cores and logical processors Windows sees. BIOS Mode says UEFI or Legacy. Secure Boot State says On, Off or Unsupported. And Installed Physical Memory shows the RAM. In the pod your servers are virtual machines, so these values come from the VM settings, not from a physical box. Your values will differ from mine.

You can read the same facts with PowerShell. Get-ComputerInfo with the Property parameter picks just the values you want, and Format-List shows one per line. Total physical memory is in bytes: about 4 gigabytes here, and Windows shows slightly less. Confirm-SecureBootUEFI returns True when Secure Boot is on, False when it is off, and an error on a legacy BIOS system. Get-Tpm tells you whether a TPM is present and ready. Run the last two as administrator. Again, your values will differ.

Here are four mistakes people make with server hardware. First, plugging both power supplies into the same PDU. Use the A and B feeds. Second, sizing a UPS by its VA number only. Check the watt rating too, and leave headroom. Third, leaving the BMC on the user network with its default password. Anyone who reaches it controls the server, so give it its own network and a strong password. Fourth, leaving empty rack spaces open. Fit blanking panels to keep hot air behind the rack.

Time to check yourself. They buy a 2U file server and a 4U storage shelf. How much rack space is that, in U and in inches? A server froze at 2 in the morning and does not answer Remote Desktop. How can you restart it from home? The load is 600 watts, and a UPS is rated 1000 VA and 600 watts. Is it a good choice? And they want BitLocker with a TPM. What does the hardware need? Pause and answer.

Let's check. One: 2U plus 4U is 6U, and 6 times 1.75 inches is 10.5 inches, in one block. Two: use the BMC. Its remote console and power controls work even when Windows has stopped. Three: no. 600 watts is the full watt rating, so there is no headroom. Pick a UPS rated at 750 watts or more. Four: the server needs a TPM 2.0 chip. Microsoft lists a TPM as required only for certain features, and BitLocker is one of them.

Let me show you SRV01 in the pod. I am signed in as Administrator. I press Windows and R, type msinfo32, and press Enter. System Information opens on System Summary. Here is the processor. This is a virtual machine, so these values come from the VM settings. Here is BIOS Mode, and below it Secure Boot State. And here is Installed Physical Memory. Now PowerShell, as administrator. Get-ComputerInfo piped to Format-List shows the logical processors, the memory in bytes and the firmware type. Confirm-SecureBootUEFI and Get-Tpm finish the picture.

Let's sum up. Servers add reliability, redundancy and remote management. They come as towers, racks or blades. Inside you find ECC memory, SATA, SAS or NVMe drives, and hot-swap bays. Two power supplies go on two feeds, and you size a UPS in both watts and VA. The BMC works when Windows does not. UEFI, Secure Boot and TPM 2.0 protect the startup.
