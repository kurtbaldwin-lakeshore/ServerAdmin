Welcome to Topic 1.3, Installing Windows Server. In Topic 1.2 you chose an edition and an installation option. Now you put those choices to work. We walk through the Windows Server 2025 setup program from the first boot to the first sign-in. You will see each important screen, learn what to pick and why, and learn how to check that the install worked. At the end, I show you a complete Server Core install in the lab pod, so you know what to expect.

Here are the six things you will be able to do after this topic. You will check the hardware, edition, option and media before you start. You will tell a clean install from an upgrade and a migration. You will follow the setup screens in order. You will pick the right image and disk, and set a strong password. You will recognize Server Manager and SConfig at first sign-in. And you will verify the install with winver and one PowerShell command.

Before you start setup, run through a short checklist. Windows Server 2025 needs at least a 1.4 gigahertz 64-bit processor, 2 gigabytes of memory, 32 gigabytes of disk and a gigabit network adapter. Those are minimums, not targets. On a virtual machine, give setup at least 1,280 megabytes of memory, or it can fail. Next, have your Topic 1.2 decisions ready: the edition and the installation option. Then you need media, an ISO file or a bootable USB drive, and the server must boot from it first.

There are three common ways to get a new version of Windows Server. A clean install puts a fresh copy on a new or wiped disk. An in-place upgrade installs the new version over the old one and keeps settings, roles and data. Windows Server 2025 can upgrade from 2012 R2 or later. A migration moves roles and data from an old server to a new one. Our lab VMs are blank, so there is nothing to upgrade or migrate. A clean install also gives everyone the same starting point.

This slide is your map. In the first row, you answer the screens: boot from the media, pick a language and keyboard, choose Install, handle the product key if your media asks, and choose the image. In the second row, you accept the license terms and choose the disk. Then setup copies files and restarts several times, which takes about 10 to 20 minutes. Finally, you set the Administrator password and sign in. Notice that only step 5, the image, differs between SRV01 and SRV-CORE.

Windows Server 2025 has a redesigned setup program, so these screens look different from Windows Server 2022. After language and keyboard, you reach Select setup option. Choose Install Windows Server, and check the box that agrees everything on the disk will be deleted. On a blank lab VM, nothing is lost. Some media then show Choose a licensing method or a product key screen. If you see it, enter the key or choose the option your instructor gives you. Volume license media skip that screen, so you just carry on.

This is the most important choice in setup. Select image lists each edition twice. A name that ends in Desktop Experience gives you the full desktop and Server Manager. The same edition without those words is Server Core. So for SRV01 you pick Datacenter with Desktop Experience, and for SRV-CORE plain Datacenter. On evaluation media, every name also contains Evaluation. Read the whole name before you select Next, because you cannot convert between the two options later. A wrong pick means a new install.

After the license terms, setup asks where to install. On a blank disk you see one line: Disk 0 Unallocated Space. Unallocated means the disk has no partitions yet. Select it and select Next. You do not create or format anything, because setup does that for you. Load driver is only for storage controllers that setup cannot see, and our pods do not need it. On Ready to install, select Install. Setup copies files and asks nothing more until the password.

So what does setup create on that space? On a UEFI computer, you get four partitions. The EFI system partition is small and uses FAT32, and the firmware starts Windows from it. The Microsoft reserved partition, or MSR, is 16 megabytes and holds no data. The Windows partition uses NTFS and becomes drive C. The Recovery partition holds the recovery tools. In PowerShell, Get-Partition shows the same list. Only the Windows partition gets a drive letter, so leave the others alone.

After the restarts, Desktop Experience shows Customize settings. The user name is already Administrator, the built-in admin account. Type the password twice and select Finish. Setup requires a complex password: characters from three of four groups, which are capital letters, small letters, digits and symbols, and not the account name. In the lab, always use the password shown in your NetLab pod, so later labs work. Server Core asks on a text screen instead: Enter, type, Tab, type again, Enter.

Now you sign in. Windows asks for Control Alt Delete first. In NetLab, use the Control Alt Delete button, because the keys on your own keyboard go to your own computer. Type the password and accept the diagnostic data screen. On Desktop Experience, Server Manager opens by itself. If a Windows Admin Center pop-up appears, close it. The Quick Start box starts with Configure this local server, which you use in Topic 1.4. The Tools menu opens the consoles and Windows PowerShell.

Server Core looks very different. There is no desktop and no Start menu, just one console window. After you set the password, Windows asks about diagnostic data, and then SConfig opens by itself. It is a numbered text menu that runs in Windows PowerShell. The banner shows the edition, a quick check. Option 2 shows a random name that starts with WIN, which you change in Topic 1.4. Option 15 exits to PowerShell, and typing SConfig brings the menu back.

How do you prove the install is what you wanted? The quick graphical check is winver. On Desktop Experience, type winver in the Start menu, the Run box or PowerShell, and press Enter. The About Windows box opens. Look for the OS Build number: Windows Server 2025 is build 26100, and the number after the dot changes with updates. The text below names the edition, Datacenter or Standard. On Server Core, you work in a text console, so use the PowerShell check on the next slide.

This PowerShell check works on both installation options. Get-ComputerInfo with the Property parameter asks for the product name, the installation type and the OS version. The command is long, so end the first line with a comma. PowerShell shows two arrows and waits for the rest. Now compare. On SRV01, the installation type says Server, which means Desktop Experience. On SRV-CORE, it says Server Core. The product name and version 10.0.26100 match on both servers. So it is one product with two installation options.

You install two servers by hand, but a company with fifty servers automates the job. First, an answer file called unattend.xml holds the answers to the setup screens, so nobody sits at the console. You build it with Windows System Image Manager. Second, you set up one reference server, run Sysprep with generalize to remove what makes it unique, and capture it as an image. Third, servers start from the network and get the image. Windows Deployment Services is being partly deprecated, and it cannot run Windows Server 2025 setup, so new deployments use Configuration Manager or similar tools.

Here are four common mistakes. First, pressing a key at Press any key to boot from CD or DVD after a restart. That starts setup over, so press a key only at the very first boot. Second, choosing the image without Desktop Experience when you wanted the desktop. Read the whole name. Third, a password that is too simple. Use three of four character groups, or simply the pod password. Fourth, creating partitions yourself. Select Unallocated Space and let setup do the work.

Time to check yourself. You are installing a new server for a branch office. First, it will run only DNS and DHCP and be managed remotely. Which kind of image do you pick? Second, after the first restart you see Press any key to boot from CD or DVD. What do you do? Third, Get-ComputerInfo shows Server Core. What opened at first sign-in? Fourth, the VM is blank. Why is an in-place upgrade not an option? Pause the video and answer all four.

Let's check. First, pick an image without Desktop Experience in the name, which is Server Core. It is smaller and has less to attack, and the edition still depends on your licensing from Topic 1.2. Second, do nothing and let the message time out, because setup continues from the disk. Third, SConfig opened in a console window. Desktop Experience would have opened Server Manager. Fourth, an upgrade needs an older Windows on the disk. A blank disk needs a clean install.

Let's install Server Core on SRV-CORE. I power on the VM and press a key to boot from the ISO. I keep the language and keyboard defaults. On Select setup option, I choose Install Windows Server and check the agree box. On Select image, I pick Datacenter, the one without Desktop Experience. I accept the terms, select Disk 0 Unallocated Space, and select Install. Copying is sped up here. See the boot message? I let it time out. Now I press Enter and type the pod password twice. After the password, Windows asks about diagnostic data, so I type 1. Then SConfig opens. I choose 15 and run Get-ComputerInfo. It says Server Core. Done.

Let's sum up. Check hardware, edition, option and media first. Labs use a clean install on a blank disk. The image name decides Desktop Experience or Server Core, and you cannot switch later. Select Unallocated Space and let setup make the partitions. Set a complex password, then sign in with Control Alt Delete. Server Manager or SConfig opens, and Get-ComputerInfo verifies the result. In Lab 1.3, about 50 minutes and practice only, you install both servers and compare them. Run the installs side by side to save time.
