Welcome to Topic 1.2, Editions and Licensing. Before anyone installs Windows Server, someone has to decide which edition to buy, how many licenses the company needs, and how the server will be installed. Those choices cost real money, and some cannot be undone later. In this video you will learn how Microsoft licenses Windows Server 2025, how to pick an edition, and how to check that a server is activated. This supports objectives 1.a and 1.b, and the Server+ exam topics on server administration.

Here is the plan. First, you will compare the Windows Server 2025 editions. Next, you will count the core licenses a server needs, which is simple arithmetic once you know the rules. Then you will compare what Standard and Datacenter allow with virtual machines, and choose between user and device Client Access Licenses. You will also choose an installation option. Finally, you will see how Windows is activated, and how to check it in Settings and from the command line.

Think of four choices you make before you build a server. The edition decides features and how many virtual machines you may run. Licensing decides how many licenses you must own. The installation option decides whether you get a desktop. And activation proves the copy uses a valid key. Now the important part. Licensing is legal compliance. Windows Server runs even if you bought too few licenses, but your organization is still breaking its agreement. Prices and terms change, so always check Microsoft's current pages.

Windows Server 2025 has four editions to know. Standard is for physical servers or a few virtual machines. Datacenter is for hosts with many virtual machines, and adds features like Storage Spaces Direct. Datacenter Azure Edition runs only as a virtual machine in Azure or Azure Local, with hotpatching and Azure Extended Networking. Essentials is for small businesses with up to 25 users and 50 devices, sold only with new single-socket servers from hardware makers. Our NetLab pod runs Datacenter on every server.

This table shows the differences that matter most. Standard allows two Windows Server virtual machines per license; Datacenter allows unlimited. Storage Spaces Direct is Datacenter only. Storage Replica works in Standard, but only with one partnership and a single volume of up to 2 terabytes. Network Controller, the heart of software-defined networking, is Datacenter only. Hotpatching is a paid Azure Arc service for Standard and Datacenter. And only Datacenter hosts can activate their VMs with AVMA. Everyday roles, like DNS and Hyper-V, are in every edition.

Standard and Datacenter are licensed by processor core, with four rules. One, license every physical core. Two, every processor counts as at least 8 cores. Three, every server needs at least 16 core licenses. Four, licenses come in 2-core and 16-core packs. Look at the example. Two processors with 6 cores each is 12 real cores. But each processor counts as 8, so the server needs 16 core licenses. We count physical cores, not hyper-threads, and CALs are bought separately.

Here is a method you can use every time. For each processor, take its cores or 8, whichever is larger. Add them up. If the total is under 16, use 16. Example A has one processor with 4 cores. It counts as 8, which is under 16, so 16. Example B has two processors with 12 cores each, so 24. Example C is tricky. Four processors with 4 cores each is only 16 real cores, but each counts as 8, so you need 32.

Now, virtual machines. When you license all the cores with Standard, you may run two Windows Server virtual machines. Want two more? License all the cores again. This is called stacking. So a 16-core host needs 16 licenses for two VMs, 32 for four, and 48 for six. With Datacenter, license the cores once and run as many VMs as the host can handle. The host itself is included if it only runs Hyper-V. And always license for the peak.

Core licenses cover the server. Client Access Licenses, or CALs, cover who or what uses it. A User CAL covers one person on any device. Ana uses a laptop, a phone and a home PC, and needs one User CAL. A Device CAL covers one device, whoever uses it. Three nurses on different shifts share one PC, so one Device CAL covers them. Count both ways and buy the smaller number. You can also mix both types. Remote Desktop needs extra RDS CALs.

Windows Server 2025 adds Pay-as-you-go. Instead of buying licenses up front, you connect the server to Azure with the Azure Arc agent, and your Azure subscription is billed per core while it is turned on. Standard and Datacenter cost the same this way, and you need no CALs for standard use, though RDS CALs are still needed. You get no extra virtual machine rights. Billing continues even when the server is shut down. Our pod has no internet, so this is a concept.

Every edition has two installation options. Desktop Experience gives you the full graphical interface and every tool. Server Core has no desktop. Server Manager, the MMC consoles and File Explorer are not there, so you use SConfig, PowerShell or remote tools. In return, Core has a much smaller attack surface, is about 4 gigabytes smaller on disk, and has fewer parts to patch. Microsoft recommends it. The catch: in Windows Server 2025 you cannot switch after installation. Changing your mind means a clean install.

Activation happens in several ways. A retail key activates one copy, and OEM servers often arrive activated. A Multiple Activation Key activates many servers, each once, online or by phone. With KMS, a server on your network activates others once at least five ask, and they renew every 180 days. AVMA lets VMs on an activated Datacenter Hyper-V host activate with no internet. The evaluation edition runs 180 days, and you can convert it with DISM and a key. In our pod, the instructor already activated the images.

On a server with Desktop Experience, the quickest check is in Settings. Select Start, Settings, System, then Activation. At the top you see the edition, such as Windows Server 2025 Datacenter, and whether it is an evaluation copy. Next is Activation state. Active means activated. Below that, Change product key lets you enter a new key, which we will not do in the pod. This is a labelled diagram, not a screenshot, so your screen may look a little different.

Here is the command-line way, which also works on Server Core. slmgr with the dli option shows license information. On its own it opens a Windows Script Host box; through cscript it prints in the console. License Status: Licensed means activated, and the description shows the channel. DISM with Get-CurrentEdition, run as administrator, shows the edition name; Eval in the name means an evaluation copy. In PowerShell, a LicenseStatus of 1 means Licensed, and 0 means Unlicensed. Your values will differ.

Let's put it together. First, a small business with up to 25 users and 50 devices, buying a new single-socket server? Essentials may fit. Second, will it run as a VM in Azure or Azure Local? Consider Azure Edition. Third, do you need Storage Spaces Direct or Network Controller? Then Datacenter. Otherwise, count the VMs at peak. Zero to two: Standard. Three to ten: price both. Eleven or more, or a changing number: Datacenter. Standard needs a full set of core licenses for every two VMs.

Four mistakes to avoid. First, licensing only the cores you use. License every physical core, with at least 8 per processor and 16 per server. Second, thinking Standard gives two VMs per 2-core pack. It is two VMs per fully licensed server. Third, installing Desktop Experience to be safe and planning to remove the GUI later. You cannot convert, so decide first. Fourth, thinking activated means fully licensed. Activation only checks the key. Cores, CALs and VM rights are still your job.

Time to check yourself. Pause the video and answer four questions. One, a server has two processors with 6 cores each. How many core licenses? Two, a 16-core host will run five Windows Server VMs on Standard. How many Standard core licenses? Three, 40 staff each use a laptop and a phone to reach one server. User or device CALs, and how many? Four, a test server shows ServerDatacenterEval. What happens after 180 days, and how do you keep it?

Let's check. One: 16 core licenses. Each processor counts as 8, and 8 plus 8 is 16. Two: 48 core licenses. Each full set of 16 allows two VMs, so five VMs need three sets, which allows up to six. Three: 40 User CALs. Device CALs would need 80, so pick the smaller. Four: the evaluation expires. Windows warns you, then shuts itself down automatically and repeatedly until you convert it to a licensed edition. So convert it first, with DISM and a retail key. An evaluation domain controller cannot be converted.

Let's look at a real server. I am signed in at the SRV01 console as Administrator. I open Windows PowerShell and type slmgr space slash dli. A Windows Script Host box shows the edition, the channel, the last five characters of the key, and the license status. Your values may differ, but you should see Licensed. I select OK. Next I type winver. About Windows shows the version and build. Finally, I open Settings, System, Activation, and read the edition and activation state.

To sum up. Standard allows two VMs per fully licensed server; Datacenter allows unlimited. License every physical core, at least 8 per processor and 16 per server. Buy user or device CALs, whichever you need fewer of. Server Core is recommended, and you cannot switch later. And licensing is legal compliance, so check Microsoft's current terms.
