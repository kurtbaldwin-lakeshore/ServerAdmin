Welcome to Topic 7.2, Creating Virtual Machines. In Topic 7.1 you built the host and its switches. Now you add virtual machines. You will walk through the New Virtual Machine Wizard and choose a generation. You will set memory, including Dynamic Memory, and the number of virtual processors. You will compare disk formats and disk types, and build a VM on a differencing disk. Finally you will look at integration services and Enhanced Session Mode, and see the PowerShell for every task.

In Hyper-V Manager, select New in the Action pane, then Virtual Machine. The left pane lists every page in order, from the name of the VM to the summary. This slide shows the Specify Generation page. Choose Generation 2, which gives you UEFI firmware and Secure Boot. Microsoft's advice is to create Generation 2 unless you have a specific reason not to. Read the warning on the page: once the VM exists, you cannot change its generation. Any page you skip keeps its default.

So what really differs? Generation 1 uses old BIOS firmware and emulated hardware. It boots from an IDE disk, an ISO or a physical DVD drive, a floppy, or a legacy network adapter. Generation 2 uses UEFI with Secure Boot on by default. It boots from a SCSI disk in VHDX format, an ISO file, or a standard network adapter. It cannot use a physical DVD drive at all. Remember, generation belongs to the VM, not the disk, and it is final. Our lab VMs are Generation 2.

Without Dynamic Memory, a VM keeps all of its startup memory all the time. With Dynamic Memory, Hyper-V moves memory between VMs as they need it. VM1 starts with 2048 megabytes, its startup RAM. When it sits idle, Hyper-V can take memory back, but never below the minimum, 512 megabytes. When it gets busy, Hyper-V adds memory again, never above the maximum. The buffer is spare memory kept free inside the VM. Memory weight decides who wins when the host runs short. Smart Paging uses disk as memory only while a VM restarts on a full host.

Here is where you set it. Right-click the VM, choose Settings, and select Memory under Hardware. Startup RAM is the memory the VM gets at boot. Below it, select Enable Dynamic Memory. You can only turn that on or off while the VM is off. Then type the Minimum RAM and Maximum RAM. Startup must sit between the two. Memory buffer is a percentage, and the Memory weight slider runs from Low to High. While the VM runs, you can still raise the maximum or lower the minimum.

Next, processors. Each virtual processor runs on one of the host's logical processors when it has work to do. VM1 gets two. Change the count while the VM is off. NUMA stands for Non-Uniform Memory Access. Each CPU socket has memory close to it, and a VM that fits inside one NUMA node runs fastest. The Processor page also has resource control: a reserve, a limit and a relative weight. Now the Server Plus view: plan the host. HV01 has 8 gigabytes. Processors can be shared by many VMs, but memory cannot be overcommitted.

A virtual hard disk is a file on the host. There are two formats. VHDX is the default. It can be up to 64 terabytes and protects its own metadata if the power fails. VHD is the older format, up to about 2 terabytes, still used for old hosts and for uploads to Azure. Then there are three types. A fixed size disk takes all its space on day one; it is fast and has no surprises. A dynamically expanding disk starts small and grows. A differencing disk stores only the changes to a parent disk.

Let's look closer at differencing disks, because VM1 uses one. The parent is the prepared base disk. VM1's own file, VM1 dot vhdx, holds only VM1's changes. When VM1 reads a block it has not changed, the read goes to the parent. Every write goes to the child. Many children can share one parent, and a child can even be a parent itself. The big rule: never change the parent. If it changes, every child breaks. So make the parent read-only first.

In Hyper-V Manager, select Edit Disk in the Action pane. The wizard asks you to locate the disk, choose an action, configure it, and finish. Compact makes a dynamic or differencing file smaller by removing empty blocks. Convert copies the disk to a new file, for example VHD to VHDX, or dynamic to fixed. Expand makes the disk bigger; after that you extend the volume inside the guest. Other actions, such as Shrink and Merge, show up only when they fit the disk you picked.

Here is VM1 in PowerShell. First, a variable holds the path of the base disk, and Set-ItemProperty makes it read-only. New-VHD with the Differencing switch and the ParentPath creates VM1 dot vhdx as a child. New-VM creates the VM with Generation 2, 2048 megabytes, the new disk and the Internal switch. Be careful: if you leave out Generation 2, you get Generation 1. Set-VMMemory turns on Dynamic Memory with a minimum of 512 and a maximum of 2048. Set-VMProcessor sets two processors.

VM2 is different. It gets a brand new disk, so New-VM uses NewVHDPath and NewVHDSizeBytes, 60 gigabytes. New-VM always makes that disk dynamic. A Generation 2 VM made by New-VM has no DVD drive, so Add-VMDvdDrive adds one with the Windows Server ISO. Set-VMFirmware puts the DVD drive first in the boot order, so Windows Setup can start from the ISO. VM1's disk is differencing, and its size, 127 gigabytes, comes from the parent. VM2's disk is dynamic, 60 gigabytes, with no parent.

Integration services are small services inside the guest that talk to the host over the VMBus, a fast internal channel. In Settings, under Management, select Integration Services. Operating system shutdown lets the host shut the guest down cleanly. Time synchronization keeps the guest clock in step with the host. Data Exchange shares simple facts. Heartbeat tells the host the guest is alive. Backup lets the host take consistent backups. Guest services is the one that is off by default. You need it to copy files in from the host, in Lab 7.3.

Virtual Machine Connection, or VMConnect, normally shows a basic console. Enhanced Session Mode uses Remote Desktop over the VMBus, so you get the clipboard, local drives and a resizable window. It takes two sides. On the host, two settings: the server policy Allow enhanced session mode, which is off by default on Windows Server, and the user setting Use enhanced session mode. Lab 7.1 set both. In the guest, Microsoft Learn says Remote Desktop Services must be enabled, and the VM must run at least Windows 10 or Windows Server 2016. Learn does not mention Server Core guests, so in the lab you record what VMConnect shows.

Two more pages in Settings. On the Security page, Enable Secure Boot is selected, and the template is Microsoft Windows. Secure Boot lets only signed boot loaders start. For a Linux guest you would pick the Microsoft UEFI Certificate Authority template. Automatic Stop Action decides what happens to the VM when the host shuts down: save its state, which is the default, turn it off, or shut down the guest cleanly. In the lab you choose shut down. Automatic Start Action and the Smart Paging file folder are set nearby.

The same settings in PowerShell. Get-VMIntegrationService lists the services. The PowerShell names differ a little from the Settings window; for example Data Exchange is Key-Value Pair Exchange, and Guest services is Guest Service Interface, which shows False. Enable-VMIntegrationService turns it on, even while the VM is running. Set-VM sets the automatic start and stop actions in one line. Get-VMFirmware shows Secure Boot on with the Microsoft Windows template. And Get-VMHost shows the Enhanced Session Mode policy, and Set-VMHost would change it.

Four mistakes to avoid. One: running New-VM without Generation 2. You get Generation 1, and you cannot fix it; you delete the VM and create it again. Two: booting or editing the parent of a differencing disk. Every child breaks, so make the parent read-only. Three: many dynamic disks on a small host volume. They grow until the volume fills and the VMs pause. Watch free space. Four: missing the prompt Press any key to boot from CD or DVD. Open VMConnect first, then start the VM.

Remember VM1: Generation 2, Dynamic Memory from 512 to 2048 megabytes, and a differencing disk on the base image. First, a VM must boot from a physical DVD drive. Which generation do you choose? Second, VM1 sits idle while the other VMs are busy. What range of memory can it have? Third, a classmate boots a VM straight from the base disk. What happens to VM1? Fourth, Copy-VMFile to VM1 fails. Which integration service is missing? Pause the video and answer all four.

The answers. One: Generation 1. Generation 2 VMs accept only ISO files in their DVD drive, and you can't change the generation later. Two: anywhere between 512 and 2048 megabytes. Hyper-V can take memory back down to the minimum, and memory weight decides who wins when the host is short. Three: VM1's disk breaks, because the parent changed under it and the blocks no longer match. That is exactly why the parent is read-only. Four: Guest services, the one integration service that is off by default.

Let's see it in the pod. On HV01 I make the base disk read-only and create VM1's differencing disk with New-VHD. In Hyper-V Manager I run the wizard: VM1, Generation 2, 2048 megabytes, the Internal switch, and the existing disk. In Settings I set the memory range, two processors, and turn on Guest services. I start VM1 and set the password. Then I build VM2 with a new 60 gigabyte disk and the ISO, press a key at the prompt, and stop at the first Setup screen. Get-VHD shows both disks.

To wrap up. Choose Generation 2 unless you need old hardware, and remember the choice is final. Dynamic Memory moves memory between the minimum and the maximum you set. Use VHDX; pick fixed for speed, dynamic for space, and differencing for many copies of one image, with a read-only parent. Guest services is off by default, and Enhanced Session Mode needs both the host and the guest.
